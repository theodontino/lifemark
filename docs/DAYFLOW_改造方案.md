# Dayflow 改造方案

2026-11-13。只读研究的结论，尚未动代码。源码位置：`Upstream/Dayflow/Dayflow/Dayflow/`。

## 1. 它是什么，有多大

Dayflow 是一个完整的 Mac 应用，我们把它整个嵌在了人生记录的 Mac 版里。

| 部分 | 行数 | 我们用不用 |
|---|---|---|
| `Views/`（它自己的界面：时间线、周报、每日简报、聊天、新手引导、设置） | 约 7.8 万 | 不用。目前唯一露出的是“屏幕记录与模型设置”那个窗口 |
| `Core/Recording`（截屏、存储、隐私排除） | 约 1.5 万 | 用 |
| `Core/Analysis` + `Core/AI`（把截图交给 AI，生成一段段活动卡片） | 约 2.5 万 | 用其中一条路线 |
| `Core/` 其余（每日简报、Flow 分心提醒、代理桥接、通知、调查） | 约 1 万 | 不用 |
| `App/` `System/` `Utilities/` `Models/` | 约 0.8 万 | 部分用 |

合计 431 个 Swift 文件、约 13.7 万行。Mac 安装包 208MB 里大部分是它的界面资源（插图、视频、字体）。

它的工作流程：

1. 开启后每 10 秒截一张屏（可调：1 / 5 / 10 / 20 / 30 / 60 秒），存在本机，默认最多占 10GB。
2. 后台每分钟检查一次，把攒够的一批截图（约 15 分钟一批）交给 AI，先转成文字描述，再归纳成“几点到几点在做什么”的卡片，带标题、类别、摘要。
3. 我们的 `DayflowLifeIntegration.swift` 读它的卡片表，把标题、类别、时间、摘要导入为待核对的时间线索。截图本身不导入。

## 2. 可以直接利用的接口

研究下来，需要的开关它基本都有，不用改它的核心逻辑：

| 需求 | 现成的入口 |
|---|---|
| 开始 / 停止记录 | `RecordingControl.start(reason:)` / `stop(reason:)` |
| 是否有录屏权限 | `ScreenRecordingPermissionNotice.isGranted` |
| 截屏间隔 | `ScreenshotConfig.interval` |
| 存储上限 | `StoragePreferences.recordingsLimitBytes` |
| 不记录哪些 App | `RecordingPrivacyPreferences`（已内置密码管理器等默认排除名单） |
| AI 用中文输出 | `LLMOutputLanguagePreferences.override = "Simplified Chinese"` |
| 用我们自己的 AI 接口 | `OpenAICompatiblePreferences.save(...)` 写入地址和模型，`KeychainManager.shared` 写入密钥，`LLMProviderRoutingStore.save(primary: .openAICompatible)` 选它为主路线 |
| 类别 | `CategoryStore`。默认是 Work / Personal / Distraction / Idle，每个类别带一段给 AI 看的英文说明 |

它支持六种 AI 来源（它自家的付费后端、Gemini、ChatGPT 命令行、Claude 命令行、OpenAI 兼容接口、本机模型）。我们只需要“OpenAI 兼容接口”这一条，和本 App 设置里填的是同一种接口。

## 3. 改造步骤

### 第一步：接成我们自己的（改动小，主要是新增一个文件）

在 `App/Mac/` 里新增中文原生设置，替换现在的“打开屏幕记录与模型设置”按钮：

- **一个开关**“自动记录 Mac 上在做什么”。打开时检查录屏权限，没有就引导去系统设置。
- **截屏间隔**：只给 10 秒 / 30 秒 / 60 秒三档。间隔越长越省钱、越省空间，细节越少。
- **占用空间上限**：默认从 10GB 降到 2GB，可选 1 / 2 / 5GB。
- **不记录的 App**：列表加添加按钮，用它现成的排除名单。
- **AI 沿用本 App 的设置**：把设置页里填的地址、模型、密钥同步写进 Dayflow 的 OpenAI 兼容配置，并把输出语言设为简体中文。用户只配一处。
- **类别对上**：把它的默认类别换成我们的八个（工作、学习、创作、通勤、生活、娱乐、休息、待分类），各配一句中文说明给 AI 参考。保留它的 Idle 系统类别，导入时跳过 Idle 卡片，不生成线索。
- **导入时兜底**：类别不在八个之内的，归到“待分类”。

### 第二步：关掉用不上的后台任务

目前启动时仍会运行、但我们用不到的：

- `DailyRecapScheduler`（每 5 分钟检查一次，生成每日总结，会调用 AI）
- `NotificationService`（它的每日 / 每周通知）
- `PrivacyShield`（依赖它的付费账号，实际不会生效）
- `InactivityMonitor`、Flow 相关的会话镜像
- `AccessibilityRecorder`（录屏时同时读取窗口文字，需要“辅助功能”权限）。要先确认 OpenAI 兼容路线是否依赖它，再决定关不关。

其中每日总结是唯一会在后台自己花 AI 费用的，应当优先关掉。

### 第三步：瘦身（可选，放最后）

把 `Views/` 和用不到的素材从编译目标里移除，安装包可以明显变小。风险是它的界面和核心之间有不少相互引用，移除时容易连带编译错误，需要逐块处理。不影响功能，可以不做。

## 4. 做之前必须清楚的三件事

1. **截图会发给云端 AI。** 这是它工作的方式：每批截图以图片形式上传给你配置的 AI 服务。本 App 目前的说明是“回顾只发送汇总，不发送录屏”，开启这个功能后这句话就不成立了。设置里必须在开关旁边明确写出“屏幕截图会发送给你配置的 AI 服务”，并且默认关闭。如果不想让截图离开本机，只能配置本机模型（`localhost`），效果和速度取决于你的机器。
2. **模型必须能看图。** 它发的是图片，不支持图片输入的模型会直接报错。设置里要提示这一点。
3. **费用和效果都没测过。** 按 10 秒一张、15 分钟一批算，一批约 90 张图，一天开 8 小时约 32 批。每批花多少钱取决于模型和图片分辨率，我没有实测数据。归纳出来的标题和类别准不准，也要真实开着跑一两天才知道。建议第一步做完后先用 60 秒间隔试一天。

## 5. 还没确认的问题

- 没走过它的新手引导（`didOnboard` 为假）时，后台分析任务是否照常运行。代码里记录开关不依赖这个标记，但分析流程是否有别处检查它，还没逐行确认。
- OpenAI 兼容路线是否需要 `AccessibilityRecorder` 的窗口文字作为输入。
- 它的卡片会不会在事后被重新归纳、合并或改写。我们的导入已经处理了“来源快照变化”（未经人工修改的线索会跟着更新），但没有在真实数据上验证过。
- 多显示器、全屏应用、锁屏和睡眠时的行为。

## 6. 建议

先做第一步和第二步里的“关掉每日总结”。改动集中在新增的设置文件和 `DayflowLifeIntegration.swift`，对 Dayflow 本身只改启动时的几行。做完后在你的 Mac 上用 60 秒间隔开一天，看线索质量和实际花费，再决定是否继续投入。
