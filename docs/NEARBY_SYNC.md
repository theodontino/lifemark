# 附近设备同步（协议 1）

此功能用于自己的 Mac 和 iPhone。设置 → 附近设备同步中开启，Mac 生成限时二维码，iPhone 扫码或粘贴完整配对码；核对两边显示的设备后分别确认。以后打开应用会自动寻找已配对的设备。iPhone 进入后台会关闭本轮网络连接，回到前台重新补齐；无需保持 Mac 常开。

## 传什么

传输账目和时间记录的名称、金额、时间、类别、备注、核对状态，包含删除历史、冲突解决历史和运行计时的生命周期版本。原始截图、录屏、定位点不通过这条同步路径传输。

2026-11-13 起，AI 的服务地址、模型和密钥会在已完成配对的设备之间同步（消息类型 `settings`）：只在通过认证的连接上发送，以修改时间较新的一份为准，空配置不会覆盖已填写的配置。“允许调用 AI”的开关不同步，每台设备各自决定。密钥到达后写入该设备的本机钥匙串。两端必须都是包含这个消息类型的版本，旧版本收到它会断开连接。Watch 继续只通过配对的 iPhone 操作计时。

两边各自开始的计时保留为并行事项。同一计时出现不同的结束或放弃结果时，待核对页展示各个结果，解决前不计入普通时间统计，也不继续显示为正常运行。离线切换后各自开始的后续事项保留。

## 通信和安全边界

使用 Network.framework 的 NWBrowser / NWListener / NWConnection，Bonjour 服务类型 `_liferecord._tcp`。广播为随机服务 UUID 和协议版本，不放个人设备名和记录。启用 `includePeerToPeer` 允许系统尝试设备间点对点 Wi-Fi；是否实际走直连取决于系统、硬件和网络环境。

TLS 仅使用 1.2、预共享密钥和 PSK AES-128-GCM-SHA256；每次配对用系统安全随机数生成 32 字节密钥。二维码含临时密钥，有效期五分钟，应只让自己的设备扫描。配对后密钥保存在本机钥匙串，不放进 iCloud。首次双方确认前不交换记录；解除配对后关闭旧连接并重建监听，禁用 TLS 会话恢复和票据以防旧凭据恢复。

## 消息与持久化

线上消息为四字节大端长度加 JSON 正文，正文上限 8 MiB。先认证 hello，再交换版本清单。单批默认最多 256 条版本、目标正文上限 4 MiB；一个不可拆分的依赖组过大时明确报错。通信层只调用 LifeStore 的 inventory、exportBatch、importBatch，不能直接修改数据库。

清单分别列账目/时间记录版本 UUID 与计时版本 UUID。导出补齐接收端缺少的版本及必要父版本，计时终态与关联的完成记录一起传输。导入在数据库事务内完成，重复版本不重复保存；版本编号相同但内容不同、协议不兼容、父链损坏、跨实体父链或循环均拒绝整批。无法解读的旧记录内容保留并进入读取问题区，避免把健康记录一起隐藏。

批次落盘后才发送确认。双方清单一致、并且完成双向摘要确认后，才显示已同步；传输中断后重新交换清单，不依赖内存中“已发送”的标记跳过数据。

## 升级与恢复

从旧版本首次打开数据库时，先使用 SQLite 在线备份保存包含已提交 WAL 内容的完整数据库，再迁移到 v5。备份与原数据库放在同一目录，文件名包含 `.pre-v5-<随机编号>.sqlite`。原版本表与删除历史保留；timerSessions 从本机状态改为可重建的显示投影，已有运行计时沿用编号、名称、类别和开始时间并补建初始版本。迁移只运行一次。

不要通过卸载应用来更新或排错。免费开发签名到期时覆盖重新签名安装，保持应用标识与签名团队。升级后的数据库包含新版本表，不能直接交给旧应用继续写入；需要回退时先保留升级后数据库，再从升级前备份恢复，恢复会失去备份之后的新记录。
