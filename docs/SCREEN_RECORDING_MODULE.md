# 人生记录屏幕记录模块

直接复用 Dayflow 的 ScreenRecorder、StorageManager、AnalysisManager、OpenAICompatibleProvider 和原有提示词/截图抽样实现，不重写采集分析核心，不移除上游源码和素材。上游 MIT 许可证与第三方声明保持保留。

## 使用

Mac 设置 → 云端 AI 中填写服务地址、支持图片输入的模型及密钥，并开启允许调用 AI；设置 → 自动记录中主动开启屏幕记录。首次需在 macOS 系统设置中允许人生记录录屏。默认关闭，每次重新打开 App 都保持关闭。地址、模型和密钥只使用人生记录的一份本机配置；若人生记录尚未填写，会迁入已有 Dayflow OpenAI 兼容设置，但不会因此启用 AI 或采集。密钥不参与设备同步。

采集间隔缺省为60秒，截图空间缺省2GB；已有设置不覆盖。可选择10/30/60秒、1/2/5GB，并修改排除软件。初始化及真正开启前均建立原有敏感软件排除名单；其他应用或浏览器中的敏感内容仍可能被截图，不能声称自动过滤全部敏感内容。调低空间限制会按原引擎清理旧材料，保留已导入的生活记录。

## 行为

- 开启后只处理本次新采集的截图，旧材料保留但不会自动积压上传。
- 定时截图 → 原引擎约15分钟分批 → 最多15张图片抽样发送至配置服务 → 生成事项 → 人生记录待核对。60秒间隔主要减少本机采集与存储，不能承诺云端费用按比例下降。
- 后台分析只使用 OpenAI 兼容路线，没有静默切换到其他服务的后备配置。最终卡片要求简体中文，内部转录可能仍为英文。
- 启用不要求辅助功能文字采集；该采集在宿主安装时明确关闭。
- 停止后不再发起新分析请求；已经发送的请求可能完成。本次会话编号逐请求检查，停止再开启后旧会话重试也不能复活。
- 修改 AI 配置时暂停屏幕模块，核对后手动重新开启；只是查看设置或读取已存密钥不会暂停。
- 页面展示状态、等待分析批次数、最近观察到完成的分析时间与失败提示。重试只针对本次会话失败批次，以异步完成回调串行进行，不占住等待队列。
- 中文八类与旧类别做兼容映射，未知归待分类，系统Idle不导入。已有自定义上游类别保留。来源更新仍使用原有版本与人工修改保护。

上游独立主窗口、新手引导、账号/付费/问卷入口、独立状态栏、自动登录配置、遥测启动、通知、每日回顾和隐私付费服务不再从宿主启动；Dock、旧链接和遗留导航均回到人生记录主窗口。仅保留必要的暂停采集启动、退出保存和数据库checkpoint。
