# 人生记录 · UX / UI 规范

版本 1 · 2026-11-13。适用于 Mac、iPhone、Apple Watch 和锁屏实时活动。
代码里的对应实现在 `Packages/LifeUI/Sources/LifeUI/Theme.swift`；规范和代码不一致时，先改规范再改代码。

新增或修改界面前先读第 1、2 节；写界面时查第 3–6 节；提交前过一遍第 9 节的清单。

---

## 1. 产品原则

这五条决定所有取舍，冲突时靠前的优先。

1. **只记录发生过的事。** 没有计划、提醒、目标和打卡。界面里不出现“应该”“还差”“完成度”。
2. **空白就是未知。** 没有记录的时间不显示成休息、浪费或 0 消费。统计只说“已记录多少”。
3. **判断归用户。** 次数多、金额大不等于浪费。App 只陈列事实，“值不值”由用户自己标。
4. **自动来的只是线索。** 截图、定位、屏幕摘要都先进待核对，用户确认后才计入统计。
5. **不替用户做不可撤销的事。** 结束计时、删除、丢弃、解除配对都必须是一次明确的点击，不能由回车、手势或误触顺带触发。

## 2. 信息架构

### 2.1 五个入口

| 入口 | 回答的问题 | 包含 |
|---|---|---|
| 现在 | 我正在做什么？今天记了什么？ | 正在计时、开始下一项、今天的时间记录 |
| 时间 | 时间去了哪里？ | 日时间线、周 / 月汇总、各类用时、同一件事通常多久 |
| 账本 | 钱去了哪里？ | 明细、分析（月度对比、商户、各类月均、后悔的消费） |
| 待核对 | 有什么要我决定？ | 冲突、读不出的记录、收支草稿、时间线索 |
| 设置 | 怎么配置？ | 同步、账期、AI、自动记录、关于 |

规则：

- **按内容分，不按动作分。** 一类内容的录入、明细、分析在同一个入口里，用顶部分段切换。不新增“回顾”“统计”这类按动作命名的入口。
- **一件事只有一个去处。** 同一份数据不在两个入口各做一个页面。可以放跳转（如“现在”里的“查看完整时间线”），不放副本。
- **需要用户动手的东西进待核对。** 它带数字角标，是唯一的待办入口。其他页面不放待办列表。
- **新增入口的门槛：** 它回答一个现有五项都回答不了的问题。否则放进现有入口的分段或面板。

### 2.2 页面骨架

每页从上到下固定为：

1. **页头**：标题，右侧是这页的控制（分段切换、前后翻页、主操作）。iPhone 上标题在导航栏，控制在下面一行。
2. **主数字**（可选）：这页最重要的一个数，如“5小时32分 已记录”“¥1,227.40 本账期净支出”。一页最多一个。
3. **主体**：Mac 上是左主右辅两栏，左边是记录，右边是汇总；iPhone 上顺序堆叠，先记录后汇总。
4. 不放页脚说明。

### 2.3 层次

- 一页只有一个最醒目的元素。有计时在跑时是计时卡片；否则是主数字或主操作按钮。
- 一页最多一个实心主按钮。其余都是描边的次按钮。弹窗另算，每个弹窗一个。
- 卡片只用来分组同类内容。不把页面上每样东西都装进卡片；主数字和页头不进卡片。

## 3. 视觉

### 3.1 颜色

所有颜色都有浅色和深色两个值，用 `lifeColor(light:dark:)` 定义。**不写只有一个值的颜色，不直接用系统蓝。**

| 名称 | 用途 | 浅色 | 深色 |
|---|---|---|---|
| `lifeAccent` | 主按钮底色、图表主色 | `#17665C` | `#4FD1B5` |
| `lifeOnAccent` | 主按钮上的文字 | `#FFFFFF` | `#0B1F1A` |
| `lifeAccentText` | 强调色文字和图标（计时数字、链接、选中项） | `#0F574E` | `#7BE3CC` |
| `lifeAccentSoft` / `lifeAccentLine` | 选中项、计时卡片的底色和描边 | `#E2F2EE` / `#A5D3C9` | `#17302B` / `#2A5F54` |
| `lifeWarnText` | 待核对、冲突、需要注意 | `#8A5800` | `#F2B45A` |
| `lifeWarnSoft` / `lifeWarnLine` | 警示卡片的底色和描边 | `#FFF3DB` / `#E5C27C` | `#2B2413` / `#6B5327` |
| `lifeGround` | 页面背景、输入框底色 | `#F4F6F5` | `#151718` |
| `lifeSurface` | 卡片、弹窗 | `#FFFFFF` | `#1F2324` |
| `lifeLine` / `lifeFieldLine` | 分隔线 / 输入框和次按钮描边 | `#DCE1DE` / `#AEB7B3` | `#2C3233` / `#4A5356` |
| 系统红 | 只用于错误信息和破坏性按钮 | | |

规则：

- **颜色有固定含义。** 青绿＝可操作或正在进行；琥珀＝等你决定；红＝出错或破坏性操作。不为了好看换色。
- **对比度：** 正文和小字 ≥ 4.5:1，24pt 以上的大字 ≥ 3:1。新颜色在两种模式下都要过。
- **不只靠颜色区分。** 待核对同时有标签文字，冲突字段同时加粗，计时中的时间线方块同时用虚线框。
- **类别色**只用在时间线方块和“各类用时”条形上，取自 `timeCategoryColor`。账本的类别条统一用主色，不给消费类别上色。

### 3.2 字体

用系统字体和系统文字样式，跟随用户的字体大小设置。**不写死字号**；确实需要特大字（计时、金额输入）时用 `@ScaledMetric`。

| 用途 | 样式 |
|---|---|
| 页面标题 | `.title` 粗体（iPhone 用导航栏大标题） |
| 主数字 | `.largeTitle` 粗体，圆体，等宽数字 |
| 计时数字 | 56pt 半粗，等宽数字，随字体设置缩放 |
| 分组标题、面板标题 | `.headline` |
| 正文、列表主行 | `.body`；条目名称用半粗 |
| 次要信息 | `.callout`，次要色 |
| 标签、时间线小字 | `.caption` |

- 所有会变化的数字（时间、金额、计数）都用等宽数字，避免跳动。
- 最小字号是 `.caption`。说明文字用 `.callout`，不用更小的。

### 3.3 间距和形状

- 间距取 4 的倍数：4、8、12、16、20、24。页面分组之间 20，卡片内 12，标签和输入框之间 6。
- 页面边距：Mac 32，iPhone 16。内容最大宽度 980，居中。
- 圆角：卡片 14，计时卡片 18，按钮和输入框 10，时间线方块 7，标签胶囊形。
- 点击区域：iPhone 最小 44pt 高，Mac 最小 32pt 高（`controlHeight`）。

## 4. 组件

用 `Theme.swift` 里已有的组件，不在页面里重新拼一个长得差不多的。

| 组件 | 用在 | 规则 |
|---|---|---|
| `LifeButtonStyle` `.lifePrimary` | 这页或这个弹窗的主操作 | 一处一个。文字是动作本身：“结束并保存”“记一笔”。 |
| `.lifeSecondary` | 其他操作 | 描边、主文字色。禁用时整体 45% 不透明度，仍能看出是按钮。 |
| `.lifeDanger` | 删除、丢弃、解除配对 | 点了之后必须再确认一次。 |
| `Chip` / `ChipPicker` | 少于十个的单选（类别、账户、评价） | 选项全部可见，不藏进下拉。不在选项里的旧值自动补一个标签显示。 |
| 系统分段控件 | 2–4 个视图或范围的切换 | 隐藏标签文字（`.labelsHidden()`），不让它看起来像多一个选项。 |
| `PeriodNav` | 按天、周、月、账期翻页 | 左右箭头加当前范围文字。不用日期步进器。 |
| `lifeField()` | 所有文字输入 | 必须有边框和底色。上方有标签（`FieldLabel`），占位符只写示例，不代替标签。 |
| `Panel` | 一组同类内容 | 标题可省。不嵌套。 |
| `RowList` + `TransactionLine` / `TimeLine` | 记录列表 | 整行可点，打开编辑。行高 ≥ 48。 |
| `BigFigure` | 页面主数字 | 数字加一句说明，一页一个。 |
| `BarRow` | 分类占比、每天时长 | 标签在左，数值在右，下面一条。按最大值归一。 |
| `Tag` | 状态标注（待核对、退款、后悔这笔） | 一行最多一个。 |
| `EmptyRecords` | 空状态 | 见 5.4。 |
| `ErrorText` | 错误 | 见 5.5。 |
| `EditorSheet` | 新建和修改的弹窗 | 字段可滚动；底栏固定：左边删除，右边“取消”和主按钮并排。 |
| `warningCard`（待核对页） | 冲突、读不出的记录 | 琥珀底色，只在待核对页用。 |

## 5. 交互

### 5.1 计时

- 开始计时最多两步：输入名称，按“开始计时”（没有计时在跑时回车也可以）。
- **有计时在跑时，回车不做任何事。** 用户必须在“切换到这一项”和“同时开始”之间点一个。
- “切换”是一次原子操作：结束当前和开始下一项要么都成功，要么都不发生。
- 每个正在计时的事项都有“结束并保存”和“放弃这次计时”。放弃要确认，并说明不会生成记录。
- 计时超过 7 天，结束前先让用户核对实际结束时间。
- 所有计时入口（主界面、Mac 菜单栏和悬浮条、手表、锁屏）都遵守以上规则，并且都能选类别。

### 5.2 录入

- 默认值来自用户上次的选择（如支付账户），第一次留空让用户选。不预填一个猜的值。
- 占位值不能当真值保存。“待确认账户”这类文字不允许入账。
- 金额输入在 iPhone 上弹数字键盘；全角数字和货币符号自动归一。
- **键盘必须能收起。** iPhone 上所有含文字输入的页面和弹窗都用 `keyboardDismissible()`：向下拖动滚动区域收起，键盘上方有“完成”按钮（数字键盘和多行输入没有回车键，只能靠它）。弹窗要放在导航容器里，否则“完成”不显示。
- “值不值”只在修改已有消费时问，新建时不问。
- 保存用主按钮，回车等同主按钮；取消用 Esc。弹窗里不放第二个实心按钮。

### 5.3 确认和撤销

| 操作 | 要求 |
|---|---|
| 删除记录、丢弃草稿、放弃计时、解除配对 | 弹确认框，标题是问句，说清后果，按钮文字是动作本身（“丢弃”），不是“确定”。 |
| 修改已有记录 | 保存时检查这条记录有没有被别处改过；改过就拒绝并提示，不覆盖。 |
| 两台设备改了同一条 | 进待核对，两个版本并排，不同的字段标出来，用户选一个。选之前不计入统计。 |
| 自动线索 | 不自动确认。定位停留必须由用户填写“当时在做什么”。 |

### 5.4 空状态

- 一句说现状，一句说下一步怎么做。例：“这个账期还没有账目。记一笔，或读一张付款截图。”
- 一页只放一个带图标的空状态。旁边的面板没数据时只显示一行灰字，不重复画图标。
- 没有数据的图表不画空坐标轴，换成一行文字。
- 不用感叹号，不卖萌，不催促。

### 5.5 错误和提示

- 错误显示在出错的操作旁边，用红色加图标（`ErrorText`），说清发生了什么和用户能做什么。
- 不把系统的英文报错直接给用户。底层错误要翻成一句人话，原文可以附在后面。
- 后台出的问题（同步断开、读不出的记录）不弹窗打断，显示在状态行或待核对页。
- 成功不需要提示，结果本身就是反馈（列表里多了一条、计时卡片出现）。

### 5.6 权限

- 只在用户打开对应功能的那一刻请求权限：开启附近同步时问本地网络，点扫码时问相机，开启自动记录时问定位、运动和录屏。
- **启动时不请求任何权限。**
- 请求前在界面上先说清用途；被拒绝后功能给出替代做法（如扫不了码就粘贴配对文字）。

### 5.7 同步状态

- 状态用一句短话：“已同步”“正在同步…”“已断开，靠近时自动重连”。不显示协议、端口、编号。
- 只在真的同步完成后说“已同步”。没配置时说“仅本机保存”，不说“等待同步”。
- Mac 侧边栏底部和设置页显示同一句状态。

## 6. 文案

- **叫法统一。** 下表左边是唯一用法。

| 用 | 不用 |
|---|---|
| 现在 / 时间 / 账本 / 待核对 / 设置 | 计时与记录、实际时间、回顾与分析 |
| 记一笔 | 新增账目、添加交易 |
| 补记 | 补录、补记实际时间 |
| 结束并保存 | 停止、完成 |
| 放弃这次计时 | 取消计时、删除计时 |
| 切换到这一项 / 同时开始 | 结束当前开始下一项、并行开始 |
| 待核对 | 待确认、草稿箱、收件箱 |
| 类别（时间）/ 分类（消费） | 混用 |
| 附近设备同步、附近同步 | 近距离同步、局域网同步 |
| 已记录 | 覆盖、覆盖时间 |

- **按钮写动作，标题写名词或问句。** 按钮：“保留这个”。确认框标题：“丢弃这条草稿？”
- **说人话。** 不出现版本、修订、实体、payload、UUID、协议这类词。记录用它的名称和时间指代，不用编号。
- **一页最多一句说明。** 解释口径的长文字放进设置或文档，不铺在每个面板下面。
- 日期：`11月13日 周五`；今天、昨天用“今天 · 11月13日”。时间：24 小时制 `14:05`。时段：`14:05 – 15:30`。
- 时长：`40分钟`、`1小时30分`、`2小时`；不到一分钟显示秒。
- 金额：`¥ 18.50`，始终两位小数；退款和收入前加 `+`。
- 中文和数字、英文之间不强制加空格，但同一页保持一致。

## 7. 可访问性

- 所有可点的东西是真正的按钮，有文字或 `accessibilityLabel`。只有图标的按钮必须有标签（如翻页箭头“前一天”）。
- 选中状态用 `.isSelected` 告诉读屏。
- 时间线方块的读屏标签包含名称、起止时间和状态。
- 装饰性元素（刻度、分隔线）对读屏隐藏。
- 字体放大到最大档时，页头控制和按钮行能换行，不截断、不重叠。用 `FlowLayout`，不用固定的横排。
- 深色和浅色都要看一遍。

## 8. 各平台

| | Mac | iPhone | Apple Watch | 锁屏 / 灵动岛 |
|---|---|---|---|---|
| 导航 | 左侧栏，选中项用强调色底 | 底部五个标签，待核对带角标 | 单页 | 无 |
| 布局 | 两栏，内容最宽 980 | 单栏堆叠 | 单栏 | 系统模板 |
| 页面标题 | 页面内 | 导航栏大标题 | 导航栏 | 无 |
| 能做什么 | 全部 | 全部 | 看当前计时、开始、结束 | 只看；点击回到 App |
| 额外入口 | 菜单栏、顶部悬浮条 | 实时活动 | — | — |

- Mac 的菜单栏和悬浮条是“现在”页的缩小版：同样的按钮文字、同样能选类别、同样要确认放弃。
- 手表是手机的遥控器，手机是唯一写入端。连不上时显示上次状态并说明，不假装成功。
- 锁屏上不放会改数据的按钮。
- iPhone 的地点记录用本 App 自己的设置（设置 → 自动记录），只记到访，不记路线；Overland 的原界面不再可达。
- Mac 屏幕采集设置仍是上游界面，入口只放在设置里，并注明部分为英文。

## 10. 目前和规范不一致的地方

写规范时已知、还没改的：

- **设置页**仍是系统表单样式：输入框没有边框，账期用步进器，“回顾的口径”是三段说明文字。
- **读截图窗口**没有按 `EditorSheet` 重做。
- **Mac 悬浮条和菜单栏、Apple Watch**没有换成新的颜色和组件。
- **AI 回顾窗口**仍用系统样式按钮。
- iPhone 上“现在”页的“读截图 / 记一笔”占了标题下的一整行，可以考虑收进导航栏右上角。
