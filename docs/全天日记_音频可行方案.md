# 全天日记：Mac 主力录音与 iPhone 轻量补记

研究日期：2026-11-13。状态：实施前方案；本轮没有开启麦克风、录音、下载模型或调用付费服务。

## 结论与边界

首版采用 Apple 原生录音/系统音频采集 + Mac 的 SpeechAnalyzer / SpeechTranscriber / SpeechDetector，本机分段转写；已有 Dayflow 提供屏幕线索。iPhone 主动短录音或一键口述，稍后交给 Mac 处理。WhisperKit 作为普通话/中英夹杂实测不合格后的替代引擎，不同时引入两套常驻模型。

全天日记表示能回顾时间、内容和来源，不能承诺设备睡眠、没带设备、手机被强退期间永不断录。Mac 离身后，轻量手机方案不会拥有完整环境声音，靠定位线索、计时和短口述补足；未知时段明确留白。

## 本机已确认

只读查询确认本机为 Apple M5 Max、64 GiB 内存；SpeechTranscriber.isAvailable=true。支持语言清单含 zh_CN / zh_TW / zh_HK / yue_CN；已安装语言含 zh_CN / zh_TW。查询最初受执行权限限制返回空清单，获得正常系统访问后重新查询确认支持；不将空清单误判为语言不支持。

上述结果仅证明接口和语言资源可用，不证明中文效果、离线全流程、能耗或长录稳定性已通过。

## 首版采集和转写

- Mac：可选“现场麦克风”“电脑声音”或两者。用 AVAudioEngine 等原生麦克风接口和 ScreenCaptureKit 分别采集，保持来源独立；不为了音频运行高帧率视频捕获，不改现有截图采集间隔。
- 每2分钟封存一个音频段，保留UTC开始时间、单调时钟偏移、来源、设备、序号与校验和。音频先落盘；转写失败只影响该段，不能损坏整天材料。
- 存储采用每轨单声道 AAC，目标32 kb/s；转写按系统要求临时解码/重采样，临时PCM不长期保存。压缩质量、采样率和实际码率必须用中文及多人场景验证，不把固定码率估算当实测。
- Mac插电时每约5分钟处理已落盘段，串行一条队列；空闲时可合并，重试限次。SpeechDetector 与转写器一起使用，减少无声段的识别开销；不假定它能独立给出可用于切除原音频的逐段人声标记。先保留压缩原音频，不根据不可靠的“静音”判断永久丢弃材料。
- Mac电池供电默认只录制、暂停重转写，插电后补齐；用户可明确切换“电池上也转写”。低电量/高温自动暂停分析，状态可见。机器睡眠不阻止，醒来记录缺口并重连音频设备。
- 不要求实时字幕、不常驻说话人分离、不持续运行大语言模型。人工确认的时间记录优先，转写和推断不能覆盖它们。
- 麦克风与电脑外放可能重复捕获；保留来源、按时间近似去重，不能直接将两份转写算成双倍时间。第一版不保证识别真实发言者，不把电脑视频中的讲话推断成用户与人交谈。

## iPhone 轻量使用

- 默认不开全天麦克风、不常驻语音识别。支持主动口述（默认几分钟）与手动开启的会话录音（可长录，带持续状态和停止按钮）。目标24–32 kb/s单轨AAC。
- 有麦克风权限及音频后台配置时可在锁屏后继续用户已开启的录音；必须处理来电、音频设备切换、权限撤销、中断和崩溃。强退后不承诺自动恢复；不录电话通话本身，不擅自采集其他App内部声音。
- 默认不在手机实时转写，回到附近网络且App可传输时把已封存片段交给Mac。手机开着可优先传输，不承诺后台一直传。
- 用户需要即时看短口述时，可单独开启手机本机短音频转写；不是全天模式的前提。

## 现有同步需要扩展

当前附近同步主要交换记录修订，明确不带原始材料，不能直接声称已能同步录音。新增独立、用户可控的“把手机录音交给这台Mac处理”能力，沿用已配对加密连接；不把base64音频塞进现有修订消息。

录音分块、校验和、断点续传、临时文件原子封存，Mac持久化后回执；重传按录音ID幂等。手机只有收到已保存确认后才能将文件按策略淘汰；不能将“已发送”当作“已安全保存”。Mac转写完成后再通过现有记录同步返还文字与线索。原音频默认不在所有设备之间复制，不经过云端AI。

## 磁盘预算（计算值，不是实测）

按32 kb/s，每轨每小时14.4 MB；两轨录8小时约230 MB、16小时约461 MB、24小时约691 MB。两轨连录3天约2.07 GB。相比16 kHz、16 bit单轨PCM每小时115.2 MB，压缩存储更适合作为日记材料。上述采用十进制MB，不含容器、索引与临时文件。

建议首版默认：

| 内容 | 限额/保留 |
|---|---|
| Mac原音频 | 3 GB或72小时，先达到者；优先淘汰已成功转写且未固定保留的旧段 |
| iPhone待交付录音 | 512 MB；未获Mac落盘确认不能默认丢弃 |
| 已有屏幕材料 | 2 GB；必须把上游另存的延时视频/预览一起盘点，不能只限制截图表 |
| 临时文件、预览、索引缓冲 | 合计约1 GB预算，临时PCM按段释放 |
| 文字与日记 | 长期保留，逐渐增长；占用计入总览，不能声称永久固定大小 |

Mac应用自管材料目标约6 GB，另列系统语音模型、可选Whisper模型和固定保留录音；不能把模型和数据库漏算后称总占用仅6 GB。磁盘剩余低于5 GB或待处理材料撑满限额时，先暂停并提示，不默默删除未转写或用户固定保留的材料。清理策略首次启用前明确说明，独立控制原音频/截图保留与正式日记删除。

## 日记形成方式

原音频 → 本机带时间转写 → 与屏幕线索、手机定位、手动计时对齐 → 日记草稿。保留证据出处和时间点，允许点开文字回听尚保留的原片段。时间已知但内容不确定时标为待核对，不因无声推断休息，不把未记录时段编成活动。

默认转写零按分钟云端费用；若要自然语言日记，可沿用现有AI服务，每日收尾生成一次（用户开启自动总结后），只发送选定文字/摘要，不发送整日原音频。页面显示实际请求次数及用量；不假定已有兼容聊天接口必然支持音频上传。关闭云端总结也能保留转写与时间线。

## 现成组件与选择依据

1. Apple SpeechAnalyzer / SpeechTranscriber：当前Mac支持普通话资源，优先使用。SpeechDetector可减少静音识别开销，仍不是零耗电，且存在漏语音的准确率权衡。[长音频介绍](https://developer.apple.com/videos/play/wwdc2025/277/)；[SpeechDetector](https://developer.apple.com/documentation/speech/speechdetector)。
2. WhisperKit（官方仓现为argmaxinc/argmax-oss-swift）：MIT，Swift/Apple端本机识别，只接WhisperKit产品，不带TTS/说话人产品。备选；项目支持大文件分块载入，禁止把整天PCM一次读进内存。[仓库](https://github.com/argmaxinc/argmax-oss-swift)；[许可](https://github.com/argmaxinc/argmax-oss-swift/blob/main/LICENSE)。
3. whisper.cpp：MIT，支持Apple Silicon和VAD，适合跨平台/命令行备选；已有苹果原生方案时不额外常驻另一套引擎。[仓库](https://github.com/ggml-org/whisper.cpp)。
4. FluidAudio：Apache-2.0，包含本机ASR/VAD等模块，中文模型与说话人模型各有许可及依赖。作为第二轮中文模型/耗能对比对象，不能把Parakeet欧语成绩当作中文效果证明。[仓库](https://github.com/FluidInference/FluidAudio)；[许可](https://github.com/FluidInference/FluidAudio/blob/main/LICENSE)。
5. Silero VAD：MIT；苹果检测器不适合时考虑，避免第一版同时引入两种人声检测器。[许可](https://github.com/snakers4/silero-vad/blob/master/LICENSE)。
6. screenpipe：产品方向相近，但当前main是Screenpipe Commercial License，不能根据旧MIT宣传直接整包复用；本方案只参考产品方向，不导入代码。[当前许可](https://github.com/screenpipe/screenpipe/blob/main/LICENSE.md)。
7. AudioTee：可参考系统音频采集；README称MIT，但当前根目录缺完整LICENSE且API自称不稳定。苹果现成采集接口已够用，首版不采用该实现。[仓库](https://github.com/makeusabrew/audiotee)。

## 实施与验收

第一步：用用户知情录制的20分钟样本比较Apple中文转写与备选，样本含独白/多人/中英夹杂/化学术语/静音/背景视频；先验证质量和每小时材料体积，不买云端服务、不默认下载多套大模型。

第二步：Mac实现双源分段存储、Apple本机转写、暂停恢复与配额；进行2小时录音和8小时日常使用测试。记录相同屏幕采集条件下“不开音频/只录音/录音并批转写”的进程能耗、CPU、内存、发热、文件体积与待处理队列；插电与电池分别测，不能拿CPU低等同耗电低。测试关开、蓝牙切换、睡眠、崩溃、磁盘满、麦克风撤权与离线重试。

第三步：iPhone短录与加密断点传送，测试锁屏、来电、强退后缺口提示、两端重复录音不双算、传送中断不丢材料。比较1小时锁屏基线/录音耗电，不先承诺每天只掉几个百分点。

第四步：把转写接入日记草稿，加入每日一次可选文字总结。首版不做声纹识人、情绪判断、全天手机常驻推理或原音频全设备复制。

系统音频与麦克风采集依据：[Apple示例](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos)。手机后台与来电边界：[Apple录音说明](https://developer.apple.com/documentation/avfaudio/avaudiosession/category-swift.struct/record)、[中断处理](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions)。
